# i18n in this repo

The CLI's own behaviour is documented in `node_modules/@drackp2m/transloco-ulid-cli/README.md`. This file only covers what is specific to this repository.

## The CLI

The i18n CLI is the npm package `@drackp2m/transloco-ulid-cli` (repo `drackp2m/transloco-ulid-cli`, bin `transloco-ulid`), a root devDependency that backs the `i18n:*` scripts. Change it in its own repo and bump it here; its suites and CI live there. `@drackp2m/*` is in `minimumReleaseAgeExclude`, so a fresh release installs without the 24-hour wait.

Paths, the import alias written into the barrel, the XLIFF sub-state prefix and the language of the notes the export writes itself come from `i18n.config.json` at the root, looked up from the working directory and, failing that, from the module itself.

What stays in `tools/scripts/i18n/` is `translate/` (the Python engine) and `bench/`, which imports the CLI as `@drackp2m/transloco-ulid-cli/<path>`.

## Translator notes

`"notesLang": "es"` is not cosmetic: the CLI only ships an English template for the notes it words itself, and `apps/web/src/app/i18n/context/notes.es.json` is its translation. When a release brings new texts to the template, `pnpm i18n:notes` adds them to that file in English, leaving the translated ones alone, and `i18n:check` warns, listing the ones still in English, until they are translated.

The Spanish prompts quote the `examples` and `gender-note` notes as they come, and `context.py` finds the `keep` names by the `No traducir nunca:` line (the `neverTranslate` text of that file), so dropping either changes every prompt and empties `keep`.

## Commands, as used here

- After `pnpm i18n:import` accepts a new key, **run `pnpm i18n:check --fix`** to regenerate `params.ts`.
- To feed a fresh translator run without touching the catalogue, prefer `pnpm i18n:export --blank` over `pnpm i18n:clear`.
- An unused key may be a usage lost in a refactor: **never run `pnpm i18n:prune` with `--yes` unless asked.**

## The VSCode extension

The extension resolves the CLI installed in the workspace (or `translocoUlidI18n.cliDir`) and imports only what the package exports by its name (`src/api.mjs`), checking its `API_VERSION`: it has no rules of its own, every diagnostic is a finding of the CLI's `analyse()`, and only a release that bumps `API_VERSION` means updating it.

It lives in the CLI's repo too, under `vscode/`, and is published to the VS Code Marketplace and Open VSX from there. The devcontainer installs it from the Marketplace (`drackp2m.transloco-ulid-i18n` in `devcontainer.json`), and the **i18n extension** launch configuration loads the working copy instead (the CLI repo is mounted at `/usr/src/transloco-ulid-cli`) to try a change before it is released. It reads `i18n.config.json` from the workspace root, and the pipe import from `translocoUlidI18n.pipeImport`.
