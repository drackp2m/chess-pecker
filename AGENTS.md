# CLAUDE.md

Guidance for any coding agent working in this repository.

## Hard rules

- **NEVER run tests, linters, builds or the app.** No Vitest, no `pnpm lint`/`lint:fix` (nor ESLint/Prettier/Stylelint directly), no `ng serve`/`nest start`/`build`, no installing browsers to "see the page". The user runs and verifies everything. Commands below are reference only.
- **Never add comments, docstrings or JSDoc** to generated code, unless explicitly asked.
- **Never hand-write or edit a migration** — change the entity and generate it.
- **Never add a `Co-Authored-By` trailer for yourself.** The commits of this repo are the user's alone.
- **Explain things once.** Don't narrate an explanation while editing and then repeat it in the summary.
- Package manager is **pnpm** — never npm or yarn.
- **Never write a user-facing text in any language other than Spanish.** `es-ES` is the source language (`DEFAULT_LANGUAGE`); every other language, English included, is translated with `pnpm i18n:export` / `pnpm i18n:import` — never by hand, and never by the agent. A new key gets its Spanish value and nothing else; the rest stay empty until they come back from the translator.
- `CHANGELOG.md` is generated by semantic-release — never hand-edit.

## Layout

pnpm workspace monorepo (`pnpm-workspace.yaml` → `apps/*`, `libs/*`):

- `apps/web` (`@chesspecker/web`) — the Angular app.
- `apps/api` (`@chesspecker/api`) — NestJS + MikroORM + Postgres.
- `libs/api-definitions` (`@chesspecker/api-definitions`) — the shapes crossing the HTTP boundary: requests, responses, state unions, route table, and runtime Zod schemas. It emits JavaScript for schema imports; import types with `import type` and schemas as value imports. Compiled with `skipLibCheck` off (the `lint` job runs that typecheck).

The root package holds no runtime dependency — only the repo-wide toolchain and scripts that delegate with `pnpm --filter`. semantic-release versions the **root** `package.json`; `@app/package` resolves there.

## Stack

Angular 22 (standalone components, signals) with `@ngrx/signals` stores, RxJS, IndexedDB via `idb`. Vitest through Angular's native builder (not Karma/Jasmine).

## Imports

Relative `./` / `../` imports are blocked by `no-restricted-imports`. Use the aliases in `apps/web/tsconfig.json`:

`@app/component`, `@app/definition`, `@app/directive`, `@app/guard`, `@app/interceptor`, `@app/layout`, `@app/model`, `@app/page`, `@app/pipe`, `@app/repository`, `@app/service`, `@app/store`, `@app/strategy`, `@app/testing`, `@app/use-case`, `@app/util`, plus `@app/package` and `@app/tools/*` (which reach into the repo root). Root singletons have exact aliases: `@app/app.config`, `@app/app.routes`, `@app/app.component`.

Anything shared with the API comes from `@chesspecker/api-definitions`; use `import type` for types and a value import for runtime schemas.

## Architecture

`apps/web/src/app/` is a clean-architecture-flavored split: `repository/` (data access), `use-case/` (business logic), `store/` (`@ngrx/signals`), `service/`, `directive/`, `component/`, `layout/`, `page/`, `pipe/`, `model/`, `definition/`, `util/`, `strategy/`, `guard/`, `interceptor/`, `testing/`.

The web app never calls `HttpClient` directly: `ApiSdkService` (`service/api-sdk.service.ts`) owns every request and the repositories call it. A call is `apiSdk.<VERB>.<module>(route, options)` with three named holes — `path` fills the route's `:params`, `params` is the body on writes and the query string on reads, `query` is always the query string — each required only when the route declares it. The verb also decides whether the request is cancelled on router navigation (reads yes, writes no; `cancellable` overrides). A cancelled request rejects with `ApiCancelledError`, which stores treat as "nothing happened"; the three session calls opt out, or the router's first navigation would cut off the boot-time session probe. In-flight reads and writes are counted separately on the SDK and painted by `SyncIndicatorComponent`, the header cloud whose chevrons go down while reading and up while writing.

The session cookies are `httpOnly`, so the web app cannot read them: `SessionStore` probes `GET /auth/refresh-session` on startup and treats a 401 as "logged out".

## Code style

Strict baseline in the root `tsconfig.base.json`, extended by every package: `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitOverride`, `noImplicitReturns`, `noPropertyAccessFromIndexSignature`, `noFallthroughCasesInSwitch`. `apps/web` adds `strictTemplates`, `strictInjectionParameters`, `strictInputAccessModifiers`, `strictStandalone`. A package that cannot meet the baseline relaxes the specific flag with a TODO — never by dropping the `extends`.

- Component selector prefix is `app`; directives camelCase, components kebab-case.
- Component class names end in `Layout`, `Page`, `Modal` or `Component`.
- Files under 400 lines, functions under 30. Both are `warn`, but lint runs with `--max-warnings 0`, so they fail like errors. They skip blank lines and comments, and don't apply to `*.spec.ts` / `*.test.ts`.
- Prettier: printWidth 100, single quotes, trailing commas everywhere, Angular parser for `*.html`.
- SCSS: `stylelint-config-standard-scss` + `stylelint-config-clean-order`. No literal colours (`color-no-hex`, `color-named` on) — use variables. `@import` banned (use `@use`/`@forward`). A `::ng-deep` must be scoped under `:host` (`angular-custom/ng-deep-requires-host`).
- **TypeScript 6 no longer auto-includes `@types/*`**, so each tsconfig declares `types` explicitly or globals like `expect`/`it` go missing: web splits `tsconfig.app.json` (`[]`) / `tsconfig.spec.json` (`["vitest/globals"]`), api splits `tsconfig.json` (`["node", "vitest/globals"]`) / `tsconfig.build.json` (`["node"]`).

## Commits and branches

commitlint enforces gitmoji + conventional commits: `<emoji> <type>: <subject>` (subject 10–75 chars, header ≤100). Pairs: ✨ feat, 🐛 fix, ♻️ refactor, 🎨 style, 🧪 test, 📚 docs, 🚀 perf, 🏗️ build, 💻 ci, 🎒 chore, ⏪ revert. Write commits in this format directly — the `prepare-commit-msg` hook falls back to interactive `git cz` on failure.

Work is committed directly to `dev`; `main` is only updated via PR from `dev` (`pnpm git:sync`), which triggers semantic-release.

## Database

Entities under `apps/api/src/module/**/*.entity.ts` are the single source of truth. Change the entity, then generate the diff: `pnpm --filter @chesspecker/api migration:create` (needs the `chesspecker-db` container up). `migration:check` lists pending, `migration:execute` applies. The integration suite replays every migration from scratch, so a mismatched migration fails there first. Migrations are generated artifacts — ignored by Prettier and ESLint.

## Commands

Everything package-scoped runs as `pnpm --filter @chesspecker/<web|api> <script>`; the root has no `start`/`test` wrappers. Extra flags pass through.

Root:

- `pnpm lint` / `pnpm lint:fix` — ESLint → Stylelint → Prettier, in that order, through `tools/scripts/lint/lint.mjs` (one unified stylish summary, `--max-warnings 0`).
- `pnpm update:deps` — the only supported way to bump deps: `ng update` inside `apps/web` for packages with migrations (Angular, `@ngrx/signals`), then `pnpm -r up --latest`. Refuses a dirty tree. `angular-eslint` lives at the root and its majors are migrated by hand.
- `pnpm test:tools` — `tools/scripts/test/tools-test.mjs`, a Vitest-shaped reporter (its own `VERSION` in the banner, an orange `unit` label, slow tests over 300 ms listed under their file, a `Failed Tests` block and the four summary rows). In a TTY it repaints a live footer — the file being run with its `passed/collected` counter, over the summary rows that grow as the run advances; the files run one at a time (`concurrency: 1`) so that footer reads like Vitest's. It drives `node:test`'s programmatic `run()` over `tools/scripts/**/*.test.mjs` — the `node:test` suites of the repo tooling (today the i18n catalogue's `message.mjs`, `plurals.mjs`, `params.mjs`, `genders.mjs` and `forms.mjs`, `check/icu.mjs` and `check/rules.mjs`, and the transfer's `fanout.mjs`, `regroup.mjs` and `merge.mjs`). No Vitest here: `tools/` is not a workspace package. Runs in `pre-commit` and in the CI `lint` job.
- `pnpm test:lock` — verifies the test files recorded in `tools/test-lock.json` still hash to what was locked (sha256 of the content, CRLF-normalized). `pnpm test:lock:select` opens the interactive picker that (re)builds that list; `pnpm test:lock --update` re-hashes the locked files to accept an intentional change; `--list` prints the lock; a positional path (`pnpm test:lock apps/api`) scopes any mode to a subtree; `--strict` turns "test file not in the lock" from a note into an error. Runs in `pre-commit` and in CI before each test suite — **never edit `tools/test-lock.json` by hand, and never `--update` a mismatch you were not asked to change**.
- `pnpm i18n:export` / `pnpm i18n:import` — hand the catalogue to a professional translator as **XLIFF 2.0** and read it back. Export writes one bilingual file per target language into `translations/` (gitignored), carrying the ULID as the unit `id`, the constant / usage sites / param types as notes, and each `{param}` as an `<originalData>`+`<ph>` pair. Flags: `--lang`, `--scope`, `--out`, a selection (`--missing` untranslated only, `--stale` translated-then-the-source-moved only, `--pending` both, none of them the whole catalogue) and `--blank`, which sends every selected unit out with an empty `<target>` and without its outdated note, so the file cannot seed a machine translator or pass an old string off as its answer. Import takes files or directories (default `translations/`), merges targets into the `<lang>.json` files in `keys.ts` order, and offers any ULID it does not know in an interactive picker — `--all-new` / `--no-new` skip it, `--dry-run` writes nothing. Accepting a new key appends it to `keys.ts`, so **run `pnpm i18n:check --fix` afterwards** to regenerate `params.ts`. The import only ever adds: a ULID the file does not carry keeps the value it had, and a unit whose `<target>` came back empty is counted as such and skipped, so a partial file never blanks the rest. A key that travelled as one unit per form (`<ULID>#plural:few`) comes back **whole**: `transfer/regroup.mjs` groups the units by ULID and recomposes them into one ICU string with `buildFrom()`, and anything short of the complete group — a form missing, empty, unexpected, or one that does not parse back — leaves the key untouched and reports it. Counts are per key, not per form.
- `pnpm i18n:clear --lang <code>[,<code>]` — blanks every translated string of those languages, so the catalogue reads as untranslated again. `--scope` narrows it to one scope, `--dry-run` only lists, `--unseal` also drops the freshness seals in `i18n/state/` (cosmetic: an empty target already reads as missing before any hash is consulted). The ULIDs stay in the file with an empty value — the shape `i18n:check --fix` settles on anyway — and the source language is refused. To feed a fresh translator run without touching the catalogue at all, prefer `pnpm i18n:export --blank`. Its counterpart is `pnpm i18n:state`, which reports fresh/stale/missing per language and seals today's sources with `--adopt`.
- `pnpm git:sync`, `pnpm pnpm:match`, `pnpm import:puzzles` — the last one is interactive and **defaults to the deployed API** (`api.chess.drackp2m.dev`), not localhost.

The i18n tooling is one file per command at the top of `tools/scripts/i18n/` — `check.mjs`, `export.mjs`, `import.mjs`, `state.mjs`, `clear.mjs` — over `catalogue/` (keys.ts, the `<lang>.json` files, context and freshness), `check/` (rules, findings, fixes, reports), `transfer/` (XLIFF build, fan-out, merge, regroup, XML) and `translate/` (the Python engine). The VSCode extension imports those same modules by path at runtime, so moving one means updating `tools/vscode-plugins/transloco-ulid-i18n/src/`.

`@chesspecker/web`: `start`, `build` (→ `apps/web/dist/chesspecker/browser`), `test`, `typecheck` (`ng build --configuration typecheck`), `preview:pwa`.

`@chesspecker/api`: `start` / `start:dev` / `start:debug` / `start:prod`, `build`, `test` (unit, `src/**/*.spec.ts`), `test:watch|cov|debug`, `test:integration` (`src/**/*.test.ts` against real Postgres — needs `chesspecker-db` up; sets `NODE_ENV=test` which switches to `DB_NAME_TEST`, and a `globalSetup` drops the schema and replays migrations), `migration:*`. Both Vitest projects live in one config, so always go through the scripts rather than a bare `vitest`.

`start:safari` (both packages) — plain HTTP with TLS terminated in front, because neither server's own TLS works in Safari. Generic script: `sh tools/scripts/start-safari.sh --source <port> [--target <port>] [--host <name>] [--env KEY=VALUE]... -- <command…>`.

pnpm version: `packageManager`, the `pnpm/action-setup` steps and the installed pnpm must agree. `packageManager` is the source of truth — the Dockerfile only bootstraps a floating `pnpm@11` via npm, and pnpm's `managePackageManagerVersions` downloads and delegates to the pinned version inside the repo. Bump by editing `packageManager` (or `pnpm self-update`, which writes the same field) then `pnpm pnpm:match --fix` — never edit the workflows by hand; the `pre-commit` hook checks it.

## CI and hooks

`.github/workflows/ci.yml` on **PRs to `main`**: `lint` (definitions typecheck, `test:tools`, `i18n:check`, then ESLint/Stylelint/Prettier), `web` (production build, then Vitest), `api` (typecheck, unit, integration, `nest build`). The compile gate goes before the suites in both, and `pnpm test:lock <package>` right after it, so a tampered test file fails before the suite runs. The `api` job runs a `services: postgres` standing in for `chesspecker-db`, with the full env block declared on the integration step. `.github/workflows/deploy.yml` on **push to `main`** does no checking: semantic-release → build → Pages.

Husky's `pre-commit` covers the same ground in order: `pnpm:match`, `lint-staged` (auto-fixes per staged file, so most style issues never need manual fixing), `test:lock` (after `lint-staged`, so a formatting fix is already in the file when it is hashed, and ahead of every suite, as in CI), `test:tools` (necessarily before `i18n:check --fix`, which rewrites `params.ts` with the very code those suites cover), `i18n:check --fix`, then the two compile gates (API `typecheck`, web `typecheck`) and only then the suites — API `test` + `test:integration`, web `test` — so nothing splits them. It needs `chesspecker-db` up.

Every job writes a step summary through `tools/scripts/*/summary.mjs` (log parsers, no-ops locally, never fail a job).

## Misc

- **A "Rebuild Container Without Cache" does not refresh `node_modules`** — they are named volumes, only seeded when created empty. After anything touching the dependency tree, `docker compose down -v` first. Postgres data survives (`.pgdata` is a bind mount).
- The Dockerfile holds two paths: the devcontainer (`base` → `deps` → `dev-attached`, ends in `tail -f /dev/null`, processes started by hand) and the API's Render image (`deps-api-prod`, `build-api`, `serve-api`). The Angular app deploys to Pages from CI, not Docker.
- One `.env` at the repo root, never committed (`.env.example` is the template). Read by Docker Compose and by the API — `env.validation.ts` calls dotenv itself, walking up for `pnpm-workspace.yaml`, because the config registers run at import time. The Angular app reads none of it: it uses the build-time `API_URL` constant in `apps/web/angular.json`'s `define` (typed in `src/typings.d.ts`), kept in step with `API_PROTOCOL`/`API_DOMAIN`/`API_PORT`/`API_PREFIX` by hand. **A `define` inside a configuration replaces the one in `options` — it is not merged**, so every new constant must be repeated in `configurations.development` or it is missing under `ng serve` only.
- `API_BASE_URL` (`definition/api.constant.ts`) rewrites `API_URL`'s hostname to the one serving the page in debug builds, keeping scheme/port/prefix — otherwise Safari drops the session cookie as third-party. `API_CORS_ALLOWED_DOMAINS` and `API_COOKIE_DOMAIN` have to match the origin actually used.
- CORS (`main.ts`) accepts **any** origin outside production, since the app is browsed from `localhost`, `MarcBook-Air.local` and whatever LAN IP the Mac has. The mkcert certificate only carries those two names — browsing by IP needs it reissued with that IP as a SAN.
- `.prettierignore`'s root-anchored `/dir` entries double as the prune list for `walk-files.mjs`, so every new package needs its `node_modules`/`dist` listed there.
